================================================================================
ШПАРГАЛКА ПО КОМАНДАМ GIT ИЗ НАШЕГО ДИАЛОГА
================================================================================

1. ПОДГОТОВКА И СОЗДАНИЕ КОММИТОВ (ЛОКАЛЬНАЯ ИСТОРИЯ)
--------------------------------------------------------------------------------
git status
  Проверяет текущее состояние репозитория: показывает, какие файлы изменены, 
  подготовлены к коммиту, а также на какой ветке вы находитесь и 
  синхронизирована ли она с сервером.

git add <имя_файла>  (или: git add .)
  Добавляет измененные файлы в область подготовленных (Staging Area) перед 
  созданием коммита. Точка (.) добавляет сразу все измененные файлы в папке.

git commit -m "сообщение"
  Фиксирует подготовленные изменения в локальной истории репозитория и 
  присваивает им краткое описание в одну строку (флаг -m = --message).

git commit
  Открывает настроенный текстовый редактор (например, Notepad++) для написания 
  подробного многострочного описания коммита.

git commit --amend -m "новый текст"
  Перезаписывает самый последний коммит: заменяет его описание (или добавляет 
  забытые файлы), исправляя опечатки до отправки на сервер.

git log -n 1
  Выводит подробную информацию о последнем сделанном коммите (автор, дата, 
  уникальный хеш и текст сообщения).


2. РАБОТА С УДАЛЕННЫМ РЕПОЗИТОРИЕМ (GITHUB)
--------------------------------------------------------------------------------
git clone <URL-адрес>
  Скачивает существующий репозиторий с GitHub на локальный компьютер, создает 
  папку проекта и автоматически настраивает связь с сервером (origin).

git remote add origin <URL-адрес>
  Связывает локальный проект с пустым удаленным репозиторием на GitHub, 
  присваивая серверу стандартное краткое имя 'origin'.

git push -u origin main
  Впервые отправляет локальную ветку 'main' на сервер 'origin' и запоминает 
  связь между ними (флаг -u = --set-upstream) для будущих коротких команд.

git push
  Отправляет новые локальные коммиты на удаленный сервер (работает после того, 
  как связь между ветками уже настроена через -u).

git push --force-with-lease origin <ветка>
  Безопасно перезаписывает историю на удаленном сервере (используется после 
  команды --amend, если коммит с опечаткой уже был отправлен на GitHub).

git fetch origin
  Загружает информацию о новых ветках и изменениях с удаленного сервера, не 
  меняя при этом ваши текущие локальные файлы.

git pull
  Скачивает свежие изменения с удаленного репозитория и сразу объединяет их с 
  вашей текущей локальной веткой.


3. УПРАВЛЕНИЕ ВЕТКАМИ И БЕЗОПАСНОЕ ПЕРЕКЛЮЧЕНИЕ
--------------------------------------------------------------------------------
git branch
  Показывает список всех локальных веток и отмечает звездочкой ту, в которой 
  вы сейчас работаете.

git branch -M main
  Принудительно переименовывает текущую главную ветку в 'main' (современный 
  стандарт GitHub).

git switch <имя_ветки>
  Переключает вас на уже существующую локальную ветку (или автоматически 
  создает копию удаленной ветки, если она есть на origin после git fetch).

git switch -c <имя_ветки>
  Создает новую ветку на основе текущего кода и сразу переключает вас в нее 
  (флаг -c = create).

git worktree add <путь_к_новой_папке> <имя_ветки>
  Создает отдельную рабочую папку на диске для другой ветки, позволяя 
  параллельно работать над двумя задачами без переключения в одной папке.


4. ВРЕМЕННОЕ СОХРАНЕНИЕ И ОТМЕНА ИЗМЕНЕНИЙ
--------------------------------------------------------------------------------
git stash
  Прячет текущие незафиксированные изменения во временный «карман» и 
  возвращает файлы к чистому состоянию последнего коммита (удобно перед 
  переключением веток).

git stash pop
  Возвращает спрятанные ранее изменения из «кармана» обратно в рабочую папку 
  и очищает запись в стеке stash.

git restore .
  Отменяет все несохраненные (незакоммиченные) изменения в текущих файлах 
  рабочей директории, возвращая их к виду последнего коммита.
